# gdscript-knowledge

Agent Skill для разработки на GDScript в Godot 4: 2D и 3D игры, интерфейсы и приложения не-игры, пошаговые и карточные игры, ИИ и навигация, процедурная генерация, плагины редактора, мультиплеер, шейдеры, экспорт на web и мобильные, связка с C# и GDExtension.

Скилл даёт ИИ-агенту (Claude Code, claude.ai и другим инструментам с поддержкой формата [Agent Skills](https://agentskills.io)) три вещи:

- **библиотеку знаний** — более 500 ссылок на документацию, статьи, книги, курсы, аддоны и открытые проекты, разложенных по категориям. У каждой ссылки есть автор, год и пояснение, зачем её читать;
- **тулчейн** — headless-режим Godot, проверка скриптов через `--check-only`, уровни предупреждений, GDScript Formatter, gdtoolkit, GUT, gdUnit4, экспорт и CI: установка, команды, порядок шагов, шаблоны `project.godot` и GitHub Actions;
- **пайплайн** — тесты до кода, проверки качества, бенчмарки, базовый замер, ревью, поиск решений в библиотеке, оптимизация и повторный замер. Правка оптимизации принимается, только если бенчмарк показал выигрыш.

В скилле есть готовые скрипты, проверенные на Godot 4.7.2: проверка всех скриптов проекта, харнесс микробенчмарков и сравнение двух прогонов.

Состояние знаний — октябрь 2026: Godot 4.7.2 stable. Тексты справочников на русском, названия источников — в оригинале.

## Состав

```
gdscript-knowledge/
├── SKILL.md                              точка входа: куда смотреть и как работать
├── scripts/
│   ├── check_scripts.sh                  --check-only по всем .gd проекта
│   ├── bench.gd                          харнесс микробенчмарков с сохранением в JSON
│   └── bench_compare.gd                  сравнение двух прогонов, код 1 при регрессии
└── references/
    ├── pipeline.md                       пайплайн разработки и оптимизации
    ├── toolchain.md                      Godot CLI, предупреждения, форматтер, тесты, CI
    ├── performance.md                    оптимизация: таблица «симптом → техника → источник»
    ├── idioms-patterns.md                типизация, стиль, что нового в 4.x, паттерны, чеклист ревью
    ├── architecture.md                   сцены, автозагрузки, Resources, сохранения, тестирование
    ├── signals-async-threads.md          сигналы, await, потоки, сеть и мультиплеер
    ├── domains.md                        особенности одиннадцати областей разработки
    └── books.md                          книги, курсы, открытые проекты, маршрут обучения
```

Агент загружает `SKILL.md`, когда задача касается GDScript или Godot. Справочники он открывает только тогда, когда нужен конкретный раздел, поэтому скилл почти не занимает контекст, пока не используется.

## Установка

**Claude Code: для всех проектов**

```bash
git clone https://github.com/Betreazen/gdscript-knowledge-skill.git
cp -r gdscript-knowledge-skill/gdscript-knowledge ~/.claude/skills/
```

**Claude Code: для одного проекта.** Скопируйте папку `gdscript-knowledge` в `.claude/skills/` в корне проекта и закоммитьте её. Тогда скилл получит вся команда.

**claude.ai.** Заархивируйте папку `gdscript-knowledge` в zip и загрузите в разделе Skills настроек claude.ai. Во frontmatter только стандартные поля `name` и `description`, поэтому загрузка проходит без ошибок.

**Другие агенты (Codex, Gemini CLI, GitHub Copilot, Cursor).** Скопируйте папку в `.agents/skills/` проекта. Этот путь читают большинство инструментов с поддержкой Agent Skills.

## Использование

Скилл срабатывает сам, когда задача касается GDScript или Godot: написание или ревью кода, структура сцен, выбор аддонов и инструментов, профилирование и оптимизация. В Claude Code его можно вызвать и явно командой `/gdscript-knowledge`.

Примеры запросов:

- «Настрой для проекта строгие предупреждения, форматтер, GUT и CI на GitHub Actions»
- «Игра проседает при сотне врагов — что можно сделать?»
- «Сделай ревью скрипта по чеклисту идиоматичного GDScript»
- «Проведи цикл оптимизации расчёта хода: бенчмарки, базовый замер, гипотезы из библиотеки, повторный замер»
- «Как разложить карточную игру на сцены, Resources и чистую логику, чтобы её можно было тестировать?»

## Пометки в справочниках

- `[устарело]` — у материала есть замена, и она указана рядом. Чаще всего так помечены советы и синтаксис Godot 3.
- `[не проверено]` — утверждение взято из одного вторичного источника; его стоит перепроверить.
- «проверено на 4.7.2» — поведение подтверждено запуском Godot 4.7.2.

Версии движка и аддонов указаны на октябрь 2026. Со временем они устаревают, поэтому перед важными решениями сверяйтесь с документацией нужной версии Godot и release notes.
